# Roadster Flight Lab

실행: https://leejuhan-1214.github.io/roadster/

GitHub Pages는 `.github/workflows/pages.yml`을 통해 `main` 브랜치의 `dist/`를 자동 배포합니다. 원본 소스도 `main`에 있으며, 기존 `gh-pages` 브랜치는 이전 배포 파일의 스냅샷으로 보존합니다.

3모터 전기 구동계의 지상 주행과 압축 기체 추진기의 비행·자세·착지를 탐구하는 브라우저 3D 실험실입니다. 한국어 교육 설명과 구조 탐색, 물리 검산을 함께 제공합니다.

이 프로젝트는 Tesla 또는 SpaceX의 공식 제품이나 실제 차량 성능 인증 도구가 아닙니다. 기본 차체는 metarex.4d의 Tesla Roadster 2020 콘셉트 외형 모델(CC BY 4.0)입니다. 2026 Rocket이나 Tesla 공식 CAD가 아니며, 추가 모터·감속기·인버터·추진기·탱크·서스펜션·배터리 형상은 교육용 도식입니다. 3모터 AWD와 200 kWh는 당시 발표 구성이지만, 내부 배치·질량분포·구동 한계·제어·타이어·공력 특성은 별도의 가정입니다.

## 3모터 구동계·비선형 타이어·대형 탱크

- 전륜 모터 1개와 후륜 좌우 모터 2개, 감속기·반축·전륜 차동장치·전력 전자장치를 구조 탐색에서 구분합니다. `drive-front`, `drive-rear-left`, `drive-rear-right`, `power-electronics`는 각각의 학습 설명으로 연결됩니다. 원본 외형 105개 메시와 별개인 기능 도식이며 실제 부품명세나 내부 CAD가 아닙니다.
- **3모터 AWD·200 kWh**는 [Tesla 2017 공식 공개 영상](https://www.youtube.com/watch?v=5RRmepp7i5g)의 당시 발표 구성입니다. **650 kW·900 N·m·감속비 9:1·최대 20,000 rpm**, 전후 토크 배분·효율·회생량은 실험 설정입니다. 발표된 가속 기록을 맞추었다고 실차 모델로 간주하지 않습니다.
- 회생제동은 회수 에너지를 배터리에 기록하고, 마찰제동은 별도 감속 경로로 계산합니다. ABS는 제동 중 바퀴 잠김을, TCS는 구동 중 헛돎을 줄이는 단순 제어입니다. 일반 Tesla EV 설명을 참고했으며 2020 Roadster의 제어 소프트웨어나 보정값은 아닙니다.
- 타이어는 전후·횡방향의 **비선형 복합 슬립**을 사용하고 최대 접지 구간 `μ_peak`와 큰 미끄러짐 구간 `μ_sliding`을 구분합니다. 힘은 접지하중과 마찰 한도를 따릅니다. **Crr 기본값 0.015**는 구름저항이며 최대 접지 계수와 별개입니다. 완전한 Magic Formula나 실측 타이어 데이터는 사용하지 않습니다.
- 노면 요철은 **0 / 3 / 6 mm**, 기본 **3 mm**의 가정 입력입니다. 각 접점의 높이·하중 변화를 탐구하는 단순 모델이며 실제 도로 측량 데이터가 아닙니다. 바퀴가 공중에 뜨면 노면 힘은 0이고 공기저항은 계속 작용합니다.
- 탱크는 **600 / 900 / 1,200 L**, 기본 **900 L**입니다. 300 K 이상 공기와 같은 초기 절대압력 **35.875 MPa**에서 기체량은 각각 **250 / 375 / 500 kg**입니다. 기본 기체 제외 질량 1,900 kg에 기본 기체 375 kg을 합한 초기 총질량은 2,275 kg입니다. 용적과 기체량은 상태방정식으로 함께 바뀝니다.
- 냉가스는 일정 압력을 유지하는 조압기 없이 **직접 블로다운**으로 공급합니다. 분사에 따른 기체량·온도·압력 감소, 유한 밸브 응답과 `Δp_line ≈ K ṁ²`의 집중 배관 손실을 적용합니다. 같은 초기 압력·온도·노즐에서 큰 탱크가 순간 추력을 높이는 것은 아닙니다. 큰 탱크의 실제 실내 포장·압력용기 구조·질량은 검증하지 않았습니다.

아래 버전별 배포·검산 수치는 해당 당시 기록입니다. 특히 600 L·Crr 0.012를 사용한 과거 수치와 현재 기본 설정을 구분해야 합니다. 이번 변경은 자동 검사 128개와 전체 JS 문법 검사를 통과했습니다. 평탄·공기저항 OFF에서 72 km/h 제동 비교는 건조 노면 0 km/h·20.1 m, 무마찰 72 km/h·100 m(각 5초)입니다. [최종 Pages 배포](https://github.com/leejuhan-1214/roadster/actions/runs/42344132554)의 build/deploy와 CI 검사가 성공했습니다. 공개 파일 43개 HTTP 200·SHA-256 일치를 확인했고, 공개 화면에서 정지 후 가속 57.4 km/h·3모터 약 3,800 rpm·타력 회생 34.6 kW를 확인했습니다. 콘솔 경고·오류는 없었습니다.

## 수평 이동과 회전 노즐 (v1.7 기록)

공중 WASD는 차체를 기울이는 대신 네 하부 짐벌 노즐을 돌립니다. 목표 자세는 현재 진행 방향을 향한 수평 자세이며, 노즐별 분사량과 요 추진기로 토크를 보상합니다. 실제 강체 자세·속도를 강제로 덮어쓰지 않습니다. 화살표 수동 피치/롤 조종은 유지합니다.

- **Space + WASD**, 또는 **H 고도 유지 + WASD**로 조작합니다. 노즐은 최대 총 편향각 25°, 회전 속도 120°/s로 제한되며 대각선에서도 한도를 넘지 않습니다. 키를 놓으면 중앙으로 돌아오고 이동 관성은 남습니다.
- **수평 이동 시연**은 2 m 상승, 노즐 좌우 전환, 착지를 실제 유한 기체 제어기로 수행합니다. 노즐 편향과 차체 롤/피치를 함께 표시합니다.
- 바퀴 사이 외측의 네 가정 노즐은 고정 지지대와 회전 벨로 구분합니다. 물리 장착점은 차체 기준 (±0.86, −0.20, ±1.08) m이며 시각 모델과 일치합니다. 플룸·입자는 회전한 실제 출구에서 시작하며, 차체·노즐·분사 방향을 함께 보간합니다. 원본 Roadster 105개 메시와 5개 가정 장치는 보존합니다.
- 노즐의 수평 힘이 CG 아래에서 만드는 토크를 고려하고, 양수·최대 추력 제약 안에서 분사량을 배분합니다. 차체 Y 방향 추력을 cosθ로 보정하며, 고도 유지에는 세계 수직 방향 투영을 사용합니다. 힘이 부족하면 포화를 표시하고 자세·고도 유지 실패를 숨기지 않습니다.
- [v1.7 Pages 배포](https://github.com/leejuhan-1214/roadster/actions/runs/42334970013)의 build/deploy 성공, 공개 파일 37개 HTTP 200 및 SHA-256 일치를 확인했습니다. 공개 시연은 노즐 중심 복귀와 착지까지 완료했으며 콘솔 오류·경고는 없었습니다.
- 자동 검증 77개 통과. 힘·토크 합산, 4방향/대각 이동, CG 변화, 짐벌 각도·회전 속도, 무기체·저압, 수동 자세 제어, 렌더링 좌표와 기존 마찰·비행·스테이지 회귀를 포함합니다.

이 짐벌 기구, 가동각, 배치와 제어기는 교육용 가정입니다. [Tesla 공식 페이지](https://www.tesla.com/roadster)의 최신 Rocket 추력 제어 설명만으로 2020 콘셉트의 동일한 노즐 기구와 순수 횡이동 제어를 확인할 수 없으며, 실제 영상과 같은 세부 설계의 복제라고 주장하지 않습니다.

## 마찰 비교와 프레임 연결 (v1.6 기록)

- **접지력 한도 μ**와 **구름저항 Crr**를 분리했습니다. Crr 기본값은 0.012, 조정 범위는 0–0.08입니다. 타이어 힘과 구름저항의 합은 여전히 μN 안에서 제한합니다. μ를 키운다고 타력 주행 감속이 무조건 커지는 모델은 아닙니다.
- **72 km/h 타력 비교 / 제동 비교**는 차체와 네 바퀴의 초기 속도를 맞추고, 팬·윙·추력·자세 제어 없이 5초간 실행합니다. 공기저항 선택은 유지합니다. 결과는 5초 후 속도와 그동안의 이동거리이며 정지거리로 일반화하지 않습니다. 최근 네 번을 비교할 수 있습니다. 수동 입력이나 마찰 조건 변경은 진행 중인 비교를 중단합니다.
- 공기저항 OFF·μ1.15에서 타력 5초 결과: Crr 0.012 → 69.8 km/h·98.5 m, Crr 0.08 → 58.3 km/h·90.5 m. Crr 0.012의 제동 결과는 μ1.15 → 0.0 km/h·18.9 m, μ0.15 → 45.5 km/h·81.6 m입니다. μ0·공기저항 OFF에서는 제동해도 72 km/h·100.0 m를 유지합니다. 모두 가정 모델 계산값입니다.
- 구름저항과 실제 타이어 제동 성분을 표시합니다. 제동력은 브레이크 토크를 반지름으로 나눈 명령값이 아니라 진행 방향을 거스르는 타이어 힘입니다. 공중 및 무마찰 조건에서는 0입니다.
- 기본 **부드럽게** 품질은 픽셀 비율을 1로 제한하고 유리 굴절의 추가 장면 렌더를 투명 재질로 대체합니다. 접지 그림자를 유지하며 **정밀 효과**에서 굴절과 동적 그림자를 다시 켤 수 있습니다. 원본 105개 메시와 5개 실험 장치는 보존합니다.
- 차체·회전·휠·카메라·추진기 표시는 500 Hz 물리 상태 사이를 보간합니다. 바퀴 회전각은 실제 시뮬레이션 시간으로 적분하여 일시정지 때 함께 멈춥니다. 비교 초기화 시 카메라도 출발점으로 동기화합니다.
- 동일 로컬 브라우저 870×668에서 기본 정지 장면 측정: 약 33 → 59 FPS, 평균 프레임 30.4 → 17.1 ms, P95 33.5 → 16.8 ms. 최종 기본 품질은 303 draw / 674,482 triangles입니다. 초기 로딩은 제외한 측정이며 모든 기기에서 60 FPS를 보장하는 수치는 아닙니다. 화면 성능 패널의 CPU 시간은 GPU 측정값이 아닙니다.

자동 테스트 71개 통과: Crr 감속 순서, μ와 Crr 역할 분리, 무마찰·공중 조건, 5초 비교, 상태 보간·일시정지와 기존 비행·구조·스테이지 회귀를 포함합니다. [v1.6 Pages 배포](https://github.com/leejuhan-1214/roadster/actions/runs/42332754856)의 build/deploy가 성공했고, 공개 파일 37개가 HTTP 200 및 로컬 SHA-256과 일치했습니다. 공개 브라우저에서 타력·제동·무마찰 비교, 분사 중 접지력 0, 110개 구조 항목과 탱크 확대를 확인했습니다. 최종 공개 기본 화면은 60 FPS·평균 16.7 ms·P95 16.8 ms였고, 콘솔 오류·경고는 없었습니다.

## 가상 비행 실험의 마찰과 탱크 (v1.5 기록)

기본 화면은 탱크·추진기를 사용하는 단일 가상 비행 실험입니다. 별도 전기 주행 모드, D/R 선택, 페달 해제 회생과 저속 HOLD 기능을 제거했습니다. 원래 지상 구동과 공중 제어는 유지합니다.

- 왼쪽 **마찰 실험**에서 건조 μ1.15, 젖음 μ0.65, 빙판 μ0.15, 무마찰 μ0을 선택합니다. 계수는 가정값이며 실험 중 바로 적용합니다.
- **공기저항 적용**을 독립적으로 켜고 끌 수 있습니다. 노면 마찰은 바퀴가 접지할 때만, 공기저항은 공중에서도 상대속도에 따라 작용합니다.
- 타이어 전후·횡방향 힘과 구름저항의 합에 μN 한도를 적용합니다. μ0은 타이어·차체의 접선 마찰이 없지만, 지면·장애물의 수직 충돌 반응은 남습니다.
- 수평 속도 km/h·m/s, 타이어 접지 마찰 합력, 차체 공기저항, 노면 계수를 탱크 압력·잔량과 함께 표시합니다. 차체 공기저항 계측값에는 별도 윙·팬의 힘을 포함하지 않습니다.
- **W/S 지상 전진/후진, 공중 WASD 기울임, B 브레이크, Space 수직 분사, Shift 전방 분사**입니다. B를 누르면 지상 모터 가속보다 우선하지만 공중 분사를 차단하지 않습니다.
- 구조 탐색에서 탱크·배관·추진기 등 5개 실험 장치를 기본 표시합니다. **압축 기체 탱크 바로 보기**를 누르면 탱크를 단독 확대하며, 반복 클릭해도 해제되지 않습니다. 105개 외형 메시와 합쳐 110개 탐색 항목입니다.
- 탱크 600 L·초기 기체 250 kg·압력 35.875 MPa·총질량 2,150 kg은 가정한 실험 조건입니다. 탱크 형상은 Tesla의 공개 실차 부품이 아닌 가상 장치로 표시합니다.

검증: 자동 테스트 65개 통과. 유한 탱크 도약, μ0에서 잔여 저항 제거, 노면별 제동, 마찰 원, 공중 타이어 힘 0, 공중 공기저항, 수평·수직 속도 분리, 탱크 기본 표시 및 기존 스테이지 회귀를 포함합니다. 로컬 및 공개 브라우저에서 탱크 확대, 가속 후 마찰 계측, B 제동, Space 분사와 기체 소모를 확인했습니다. [v1.5 배포 실행](https://github.com/leejuhan-1214/roadster/actions/runs/42329439490)의 build/deploy 성공, 공개 런타임 35개 파일의 HTTP 200 및 로컬 SHA-256 일치를 확인했습니다. 공개 콘솔 오류·경고는 없었습니다.

## 세부 부품 탐색 (v1.3 기록)

2020 콘셉트 외형을 유지하면서 원본 105개 메시(85개 아티스트 오브젝트)를 모두 개별 선택할 수 있게 했습니다. 기존 8개 학습 주제는 물리 설명으로 유지하고, 외장·유리·실내·등화·바퀴·마감 부위 분류, 이름·재질 검색, 개별 숨김, 단독 보기, 가까이 보기와 조립 초기화를 추가했습니다. 한 원본 오브젝트의 재질 표면은 함께 분해되며, 디스크 회전과 캘리퍼 고정 관계를 유지합니다.

105는 원본 메시 수이며 Tesla의 실제 부품 수나 전수 BOM이 아닙니다. 확인되지 않은 내부 장치를 실제 CAD처럼 만들지 않았습니다. 탱크·배터리·서스펜션·추진기·윙 5개 가정 장치는 기본 탐색에서 표시하며 체크를 해제해 숨길 수 있습니다. 주행 모드에서는 기존 교육용 물리 모델을 유지합니다. 사용자 GLB는 주행 외형만 바꾸며 구조 탐색은 Roadster 원본을 표시합니다.

## 실행

Python 3이 있으면 별도 빌드 없이 실행할 수 있습니다. 이 프로젝트 폴더에서:

```sh
python3 -m http.server 8080 --directory dist
```

브라우저에서 `http://localhost:8080`을 엽니다. ES 모듈을 사용하므로 HTML 파일을 `file://`로 직접 열지 않습니다. Three.js 파일은 `dist/vendor`에 포함되어 있습니다.

개발용 의존성 설치 및 수치 검사:

```sh
npm ci --ignore-scripts
npm run check
npm test
```

검사 출력의 통과 여부와 오차를 확인하십시오. 통합 앱이 완성된 시점의 실제 실행 결과는 배포 설명을 따릅니다. 렌더링이 부드럽다는 사실과 계산이 정확하다는 사실은 서로 다른 검증입니다.

## 세 가지 관찰 방식

- **주행·비행:** 도로에서 가속·조향하고, 압축 기체를 사용해 이륙·회전·착지합니다. 압력과 기체 잔량이 줄어드는 모습을 함께 살펴봅니다.
- **구조 탐색:** 드래그로 차체 주위 시점을 회전하고, 스크롤을 위로 또는 트랙패드 핀치를 바깥으로 움직이면 부품이 단계적으로 분해됩니다. 반대 동작으로 조립하며 기존 슬라이더도 사용할 수 있습니다. 분해된 부품을 선택하여 역할과 수식을 읽습니다. 표시된 내부 구조는 교육용 가정입니다.
- **물리 실험:** 자유낙하, 대칭 추력, 이상 로켓 방정식, 착지 감쇠와 시간 간격 수렴 같은 축소 조건으로 계산을 확인합니다.

자동 도약은 0.6 / 2 / 3 m를 선택할 수 있고 기본 목표는 3 m입니다. 실제 최고 높이와 접촉 속력은 선택한 탱크·노면·기체 잔량에 따라 달라지므로 해당 실행의 계측값으로 확인합니다. 고도 유지 목표 슬라이더는 10 m까지 설정되지만 도달·유지를 보장하지 않습니다. 수동 Space 분사에는 고도 하드캡이 없으며, 오래 누르면 착지 감속용 기체가 부족해집니다. 시연은 가정한 탱크·노즐·제어기 조건에서의 계산 예시이며, 실제 차량의 체공시간·비행 안전성을 입증하지 않습니다.

## 모델과 단위

내부 계산은 SI 단위를 사용합니다. 위치 m, 속도 m/s, 질량 kg, 힘 N, 토크 N·m, 압력 Pa, 온도 K, 에너지 J입니다. 화면에서 km/h·MPa·도 단위로 바꾸어 표시할 수 있습니다.

Three.js와 물리 모듈의 오른손 좌표계는 **X 전방, Y 위쪽, Z 오른쪽**입니다. 차량의 코는 +X를 향하며, 회전 상태는 쿼터니언으로 저장합니다. 추진기 방향은 현재 차체 자세에 따라 지면 좌표계로 변환됩니다.

기본 기체 제외 질량 1,900 kg은 가정값입니다. 기본 탱크 900 L와 기체 375 kg은 실험용 입력이며 2020 콘셉트의 확정 사양이 아닙니다. 600 / 900 / 1,200 L 선택은 같은 300 K·35.875 MPa에서 초기 기체량 250 / 375 / 500 kg에 대응합니다. 이 압력은 실제 차량의 측정된 충전압력이 아닙니다. 체적·기체량·압력·온도는 상태방정식으로 연결되므로 네 값을 독립적으로 고정할 수 없습니다. 분사 후 기체량·온도·압력은 계속 변합니다.

## 구현 원칙과 한계

- **유한 기체:** 추력과 질량 유량을 함께 계산하며 탱크 질량과 내부에너지를 감소시킵니다. 빠른 방출을 잘 섞인 단열 이상기체로 근사합니다. 조압기 없는 직접 블로다운과 유량 제곱의 집중 배관 손실을 적용합니다. 고압 실기체 효과·탱크 벽 열전달·배관 내부의 상세 압축성 과도 유동은 생략합니다.
- **노즐:** 단순 수축 노즐의 초크·비초크 유동과 출구 압력 추력을 사용합니다. 실제 노즐 형상·성능 지도·방향별 최대 추력은 확보하지 못했습니다.
- **회전:** 추진기별 작용점과 힘으로 토크를 계산합니다. 고정 무게중심·관성 근사를 사용합니다. 기체 소모에 따른 관성과 배출 각운동량을 엄밀하게 계산하는 모델은 아닙니다.
- **제어:** 목표 오차로 필요한 출력을 구하되 가용 추력과 밸브 응답에 제한을 둡니다. 제어기가 명령했다고 실제로 그 힘을 만들 수 있는 것은 아닙니다.
- **접촉:** 네 모서리의 유연한 접촉·서스펜션 힘을 차체에 연결합니다. 바퀴의 회전은 계산하지만 차체와 각 바퀴의 수직 질량을 따로 푸는 완전한 1/4 차량 모델은 아닙니다. 한계 변형·충돌의 수치 처리를 실차의 충돌 안전성으로 해석하지 않습니다.
- **구동계:** 앞 1개·뒤 2개의 모터, 감속기와 바퀴 회전·출력·토크·최대 회전수 제한을 연결합니다. 200 kWh는 당시 발표 용량이며 내부 모듈 배치는 도식입니다. 650 kW·900 N·m·9:1·20,000 rpm 및 효율은 가정입니다. 회생제동·ABS·TCS는 단순화한 제어이며 실제 Tesla 소프트웨어가 아닙니다.
- **타이어:** 비선형 종·횡방향 복합 슬립, 최대·미끄러짐 마찰 계수와 구름저항을 구분합니다. 기본 Crr는 0.015이며 0·3·6 mm의 단순 노면 요철을 선택합니다. 실제 Roadster의 타이어 측정값, 전체 Magic Formula, 온도·마모·내부 변형이나 복잡한 도로 형상까지 재현하지 않습니다. 공중의 바퀴에는 접지력을 주지 않습니다.
- **공기력과 팬:** 공기에 대한 상대 속도로 항력·윙 힘을 계산합니다. 팬의 지면 흡착은 차고에 따라 감소하며 비행용 양력과 구분합니다. 실측 풍동·팬 지도를 사용하는 모델은 아닙니다.
- **수치해석:** 화면 갱신과 고정 물리 시간 간격을 분리합니다. 시간 간격을 줄여 사건 시각·속도·높이 등이 수렴하는지 검사합니다. 충돌에 필요한 힘과 충격량을 설명하지 않는 순간 위치 이동은 물리 성능으로 간주하지 않습니다.
- **에너지:** 탱크 내부에너지, 차량 기계에너지, 배터리와 손실은 서로 다릅니다. 차량의 운동에너지만 보존되어야 한다고 가정하지 않습니다. 배출 기체가 운반하는 에너지도 고려해야 합니다.

완벽하게 동일한 디지털 실차를 만들려면 질량분포, 관성행렬, 타이어·서스펜션, 방향별 추진기 성능, 팬·공력 지도와 실측 궤적이 필요합니다. 이 프로젝트의 목표는 가정과 오차를 확인할 수 있는 교육용 모델입니다.

## 세부 차량 기하와 질량 배치

`cgX/cgY/cgZ`는 차체의 기하 기준점에서 무게중심까지의 고정 오프셋(m)입니다. `inertiaRoll/inertiaYaw/inertiaPitch`는 그 무게중심을 지나는 X/Y/Z축의 주관성모멘트(kg·m²)입니다. 질량과 관성은 독립 입력이며, 모두 공개되지 않은 실차 값의 대용 가정입니다. 기체 소모로 총질량은 줄지만, 이 버전에서는 무게중심과 관성의 시간 변화·배출 기체의 회전 운동량은 여전히 생략합니다. 외형 파일로 질량 배치가 자동 추정되는 것은 아닙니다.

계산 위치 `state.pos`는 세계 좌표의 무게중심입니다. 차체 기하 기준점은 `bodyPosition = state.pos − R(q)cg`이며, 타이어·공력·팬·차체 충돌과 추진기 레버암에 같은 오프셋을 적용합니다. 따라서 무게중심을 앞쪽으로 옮기면 앞바퀴 정적 하중이 늘고, 높이면 가속·제동 시 앞뒤 하중 이동이 커집니다. 관성을 키우면 같은 토크의 각가속도가 작아집니다. 단순 수평 정적 조건에서는 `N_front/(mg) ≈ 1/2 + cgX/wheelbase`, 가속 중에는 `ΔN ≈ mah/wheelbase`로 이해할 수 있습니다. 실제 계산은 네 접점의 스프링·댐퍼 힘과 토크를 합하므로 자세와 과도응답도 포함됩니다.

`wheelbase`(휠베이스)와 `trackWidth`(윤거)는 바퀴 접점 기하를 바꿉니다. 앞바퀴는 Ackermann 기하에 따라 안쪽이 더 많이 꺾입니다. 휠베이스 L, 윤거 t, 회전 반경 R에서 `tan δ_inner = L/(R−t/2)`, `tan δ_outer = L/(R+t/2)`이며 실제 운동은 여전히 타이어 슬립과 마찰 한계로 결정됩니다. 서스펜션 링크 상세 기구학, 조향 탄성, 타이어 온도·마모, 실측 공력 지도까지 재현한 모델은 아닙니다.

## 스테이지와 공중 조종 (v1.2 이후 기록)

왼쪽의 **스테이지 시작** 버튼으로 7개 구조물과 3단계 코스를 시작합니다. 왼쪽 주행 게이트 → 공중 링 → 착지 패드에서 정지 순서입니다. 다음 목표는 노란색, 완료 목표는 녹색으로 표시합니다. 제한 시간은 시뮬레이션 시간 120초이며 일시정지·구조 탐색 중에는 진행하지 않습니다. R로 재시작하고, 자유 주행 버튼으로 구조물을 제거합니다. 시작·재시작 시 차량과 탱크를 초기화하며 진행 중에는 기체를 보충하지 않습니다.

지상 WASD는 모터·조향을 조작합니다. 공중 WASD는 **차량 기준** 전후·좌우 방향으로 최대 25° 짐벌 노즐 편향을 요청하고, 차체는 수평 자세를 목표로 제어합니다(v1.7). 키보드가 순간적인 수평 속도를 부여하지 않습니다. Space는 분사이며 고도 유지보다 우선합니다. 키를 놓으면 활성화된 자세 안정화가 수평을 회복합니다. Q/E는 요, 화살표는 수동 피치·롤입니다. 공중에서 접지력을 주지 않습니다.

처음에는 약 20–25 km/h로 접근해 링 약 8 m 앞에서 Space를 짧게 눌러 이륙하고, 하강 중 다시 분사해 감속하는 방식으로 연습할 수 있습니다. B는 지상 브레이크입니다. 착지 목표는 패드 반경 5 m 안에서 3개 이상 바퀴가 접촉하고, 수평 속력 1.5 m/s 미만·수직 속력 0.5 m/s 미만을 0.5초 유지하는 것입니다. 기체 부족이나 과도한 속도에서는 성공하지 못할 수 있습니다.

스테이지의 블록·아치와 충돌하며 박스 상면에는 개별 바퀴 접촉이 적용됩니다. 차체는 회전하는 상자(OBB), 장애물은 고정 축정렬 상자(AABB)로 근사합니다. 교차 검사와 충격량·마찰, 잔여 관통 보정을 사용하며 정밀 외형 메시 충돌·변형·파손 또는 일반적인 연속 충돌 검출은 아닙니다. 목표 링은 통과 판정용이며 먼 건물·콘·산은 배경입니다.

스테이지 완주 회귀 검사는 일반 모터·조향·자세·Space형 분사 입력으로 약 7.27초, 최고 약 2.73 m, 기체 약154.5 kg 잔량에서 완료했습니다. 조향·자세는 연속 피드백 입력을 사용했으므로 사람이 키보드로 쉽게 완주한다는 검증은 아닙니다. 자동 테스트 57개를 통과했으며 입력 전환, 벽·천장·플랫폼 충돌, 단계별 분해, 카메라 시점 유지, 코스 판정·완주를 포함합니다. 공개 사이트의 브라우저 확인 범위는 위 검산 항목에 기재했으며, 마우스 드래그·트랙패드 핀치와 WASD 전체 코스 완주는 이번 확인 범위에 포함하지 않았습니다.

## GitHub Pages 업데이트

`main`에서 `dist/`를 수정하고 다음 검사를 실행한 뒤 변경 사항을 커밋하고 `main`에 push합니다.

```sh
npm ci --ignore-scripts
npm run check
npm test
git push origin main
```

`.github/workflows/pages.yml`은 `main`의 `dist/**`, `tests/**`, `package*.json` 또는 workflow 파일이 변경되면 실행됩니다. 의존성 설치, JavaScript 문법 검사와 자동 테스트, 정적 진입점·모델 파일 검사를 통과한 뒤 `dist/`를 아티팩트로 업로드하여 배포합니다. README 등 문서만 변경한 push는 배포를 실행하지 않습니다. 필요하면 GitHub Actions의 **Deploy Roadster to GitHub Pages**에서 **Run workflow**로 수동 실행할 수 있습니다.

저장소 Settings → Pages의 Source는 **GitHub Actions**(`build_type: workflow`)를 유지합니다. `github-pages` 환경은 `main` 배포를 허용하도록 설정되어 있습니다. Actions에서 build와 deploy가 모두 성공한 다음 공개 URL을 확인합니다. 배포 주소는 https://leejuhan-1214.github.io/roadster/ 입니다.

2026-11-07 [v1.5 당시 배포 실행 42329439490](https://github.com/leejuhan-1214/roadster/actions/runs/42329439490)에서 build와 deploy 성공 및 공개 사이트 응답을 확인했습니다. 이후 배포 결과는 각 버전 기록을 따릅니다.

기존 `gh-pages` 브랜치는 보존된 스냅샷이며 현재 배포 소스가 아닙니다. `scripts/publish_pages.py`와 `scripts/deploy_github.py`는 이전 브랜치 배포 방식을 위한 도구이므로 현재 workflow 운영에서는 실행하지 마세요. 특히 `deploy_github.py`는 Pages 소스를 `gh-pages`로 다시 설정하므로 현재 자동 배포 설정을 되돌릴 수 있습니다.
