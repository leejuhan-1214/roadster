# Roadster Flight Lab

실행: https://leejuhan-1214.github.io/roadster/

GitHub Pages는 `.github/workflows/pages.yml`을 통해 `main` 브랜치의 `dist/`를 자동 배포합니다. 원본 소스도 `main`에 있으며, 기존 `gh-pages` 브랜치는 이전 배포 파일의 스냅샷으로 보존합니다.

2020 Roadster 콘셉트의 전기 주행과 부품 구조를 탐구하는 브라우저 3D 실험실입니다. 기본은 3모터 AWD 전기 주행 근사이며, 압축 기체 추진기 비행은 별도로 선택하는 가정 실험입니다. 한국어 교육 설명과 물리 검산을 함께 제공합니다.

이 프로젝트는 Tesla 또는 SpaceX의 공식 제품이나 실제 차량 성능 인증 도구가 아닙니다. 기본 차체는 metarex.4d의 Tesla Roadster 2020 콘셉트 외형 모델(CC BY 4.0)입니다. 2026 Rocket이나 Tesla 공식 CAD가 아니며, 추가 추진기·탱크·서스펜션·배터리는 교육용 가정 부품입니다. 공개된 일부 기능을 참고하지만 질량분포, 노즐 배치와 면적, 타이어·서스펜션·공력 특성에는 명시한 가정이 있습니다.

## 전기 주행과 마찰 (v1.4)

기본 주행을 전기 모드로 변경했습니다. 2017 공식 발표의 앞 1개·뒤 2개 모터 AWD 및 200 kWh 구성을 참고하고, 일반 Tesla EV 설명서의 가속 해제 회생·마찰 브레이크·저속 정지 유지 원리를 근사합니다. 실제 2020 콘셉트의 제어 소프트웨어나 비공개 타이어 데이터를 재현한 것은 아닙니다.

- 수평 속도 √(vx²+vz²)를 km/h·m/s로 표시하고 수직 속도와 구분합니다.
- W 또는 가속 버튼을 누르면 선택한 D/R 방향으로 가속합니다. S·Space·B는 브레이크이며 가속보다 우선합니다. 1/2 또는 D/R 버튼으로 방향을 선택하며, 접지하고 0.5 m/s 미만일 때만 전환합니다.
- 가속을 놓으면 모터 저항 토크로 감속하면서 배터리로 에너지를 회수합니다. 충전량 95–100%에서 회수 제한을 적용하며, 시작 충전량은 80%입니다. 회생 해제 시 구름저항·공기저항으로 타력 주행합니다.
- 구동·제동·코너링·구름저항을 합한 타이어 힘은 각 바퀴의 μN 한계를 넘지 않습니다. 건조(1.15)·젖음(0.65)·빙판(0.15)은 비교를 위한 가정 계수입니다. 공중에는 타이어 접지력을 만들지 않습니다.
- 모터 출력, 회생 전력, 타이어 수평 합력, 브레이크 요구력을 표시합니다. 브레이크 요구력은 브레이크 토크/반경의 합이며 실제 노면 제동력과 다릅니다.
- 전기 모드에서는 탱크 질량·추진기·팬·가정 윙을 사용하지 않습니다. 비행 실험으로 전환하면 기존 도약·스테이지와 가정 장치를 사용할 수 있습니다.

질량 1,900 kg, 모터 합산 650 kW·900 N·m, 고정 앞:뒤 토크 분배 1:2, 회생 감속 목표 1.8 m/s²·기계 회수 한도 80 kW·회수 효율 72%는 교육용 가정입니다. 정밀 ABS·TCS·실차 토크 벡터링, 배터리 온도에 따른 제한과 실측 회생 곡선은 구현하지 않았습니다. 속도·가속·정지거리를 실차 성능으로 해석하지 않습니다.

## 세부 부품 탐색 (v1.3)

2020 콘셉트 외형을 유지하면서 원본 105개 메시(85개 아티스트 오브젝트)를 모두 개별 선택할 수 있게 했습니다. 기존 8개 학습 주제는 물리 설명으로 유지하고, 외장·유리·실내·등화·바퀴·마감 부위 분류, 이름·재질 검색, 개별 숨김, 단독 보기, 가까이 보기와 조립 초기화를 추가했습니다. 한 원본 오브젝트의 재질 표면은 함께 분해되며, 디스크 회전과 캘리퍼 고정 관계를 유지합니다.

105는 원본 메시 수이며 Tesla의 실제 부품 수나 전수 BOM이 아닙니다. 확인되지 않은 내부 장치를 실제 CAD처럼 만들지 않았습니다. 탱크·배터리·서스펜션·추진기·윙 5개 가정 장치는 기본 탐색에서 숨기고 선택적으로 표시합니다. 기본 전기 주행에서는 가정 비행 장치를 숨기며, 추진기 비행 실험을 선택하면 기존 장치를 사용합니다. 사용자 GLB는 주행 외형만 바꾸며 구조 탐색은 Roadster 원본을 표시합니다.

## 실행

Python 3이 있으면 별도 빌드 없이 실행할 수 있습니다. 이 프로젝트 폴더에서:

```sh
python3 -m http.server 8080 --directory dist
```

브라우저에서 `http://localhost:8080`을 엽니다. ES 모듈을 사용하므로 HTML 파일을 `file://`로 직접 열지 않습니다. Three.js 파일은 `dist/vendor`에 포함되어 있습니다.

개발용 의존성 설치 및 수치 검사:

```sh
npm ci --ignore-scripts
npm run check
npm test
```

검사 출력의 통과 여부와 오차를 확인하십시오. 통합 앱이 완성된 시점의 실제 실행 결과는 배포 설명을 따릅니다. 렌더링이 부드럽다는 사실과 계산이 정확하다는 사실은 서로 다른 검증입니다.

## 세 가지 관찰 방식

- **실험 주행:** 기본 전기 주행으로 가속·회생·제동·노면 접지를 관찰합니다. 주행 방식을 비행 실험으로 바꾸면 압축 기체를 사용한 이륙·회전·착지를 관찰할 수 있습니다.
- **구조 탐색:** 드래그로 차체 주위 시점을 회전하고, 스크롤을 위로 또는 트랙패드 핀치를 바깥으로 움직이면 부품이 단계적으로 분해됩니다. 반대 동작으로 조립하며 기존 슬라이더도 사용할 수 있습니다. 분해된 부품을 선택하여 역할과 수식을 읽습니다. 표시된 내부 구조는 교육용 가정입니다.
- **물리 실험:** 자유낙하, 대칭 추력, 이상 로켓 방정식, 착지 감쇠와 시간 간격 수렴 같은 축소 조건으로 계산을 확인합니다.

자동 도약은 0.6 / 2 / 3 m를 선택할 수 있고 기본 목표는 3 m입니다. 기본 물리 조건에서 실제 계산 최고 높이는 약 3.148 m, 첫 바퀴 접촉 수직 속력은 약 0.695 m/s입니다. 고도 유지 목표 슬라이더는 10 m까지 설정되지만 도달·유지를 보장하지 않습니다. 수동 Space 분사에는 고도 하드캡이 없으며, 오래 누르면 착지 감속용 기체가 부족해집니다. 시연은 가정한 탱크·노즐·제어기 조건에서의 계산 예시이며, 실제 차량의 체공시간·비행 안전성을 입증하지 않습니다.

## 모델과 단위

내부 계산은 SI 단위를 사용합니다. 위치 m, 속도 m/s, 질량 kg, 힘 N, 토크 N·m, 압력 Pa, 온도 K, 에너지 J입니다. 화면에서 km/h·MPa·도 단위로 바꾸어 표시할 수 있습니다.

Three.js와 물리 모듈의 오른손 좌표계는 **X 전방, Y 위쪽, Z 오른쪽**입니다. 차량의 코는 +X를 향하며, 회전 상태는 쿼터니언으로 저장합니다. 추진기 방향은 현재 차체 자세에 따라 지면 좌표계로 변환됩니다.

기본 기체 제외 질량 1,900 kg은 가정값입니다. 600 L와 약 250 kg은 실험용 입력이며 2020 콘셉트의 확정 사양이 아닙니다. 300 K 이상 공기 가정에서 초기 절대압력 35.875 MPa를 계산합니다. 이 압력을 실제 차량의 측정된 충전압력으로 해석하지 않습니다. 체적·기체량·압력·온도는 상태방정식으로 연결되므로 네 값을 독립적으로 고정할 수 없습니다.

## 구현 원칙과 한계

- **유한 기체:** 추력과 질량 유량을 함께 계산하며 탱크 질량과 내부에너지를 감소시킵니다. 빠른 방출을 잘 섞인 단열 이상기체로 근사합니다. 고압 실기체 효과, 탱크 벽 열전달과 배관의 상세 유동은 생략합니다.
- **노즐:** 단순 수축 노즐의 초크·비초크 유동과 출구 압력 추력을 사용합니다. 실제 노즐 형상·성능 지도·방향별 최대 추력은 확보하지 못했습니다.
- **회전:** 추진기별 작용점과 힘으로 토크를 계산합니다. 고정 무게중심·관성 근사를 사용합니다. 기체 소모에 따른 관성과 배출 각운동량을 엄밀하게 계산하는 모델은 아닙니다.
- **제어:** 목표 오차로 필요한 출력을 구하되 가용 추력과 밸브 응답에 제한을 둡니다. 제어기가 명령했다고 실제로 그 힘을 만들 수 있는 것은 아닙니다.
- **접촉:** 네 모서리의 유연한 접촉·서스펜션 힘을 차체에 연결합니다. 바퀴의 회전은 계산하지만 차체와 각 바퀴의 수직 질량을 따로 푸는 완전한 1/4 차량 모델은 아닙니다. 한계 변형·충돌의 수치 처리를 실차의 충돌 안전성으로 해석하지 않습니다.
- **타이어:** 종·횡방향 슬립과 마찰 원을 사용하는 축소 모델입니다. 온도·마모·복잡한 노면·타이어 내부 변형은 생략합니다. 공중의 바퀴에는 접지력을 주지 않습니다.
- **공기력과 팬:** 공기에 대한 상대 속도로 항력·윙 힘을 계산합니다. 팬의 지면 흡착은 차고에 따라 감소하며 비행용 양력과 구분합니다. 실측 풍동·팬 지도를 사용하는 모델은 아닙니다.
- **수치해석:** 화면 갱신과 고정 물리 시간 간격을 분리합니다. 시간 간격을 줄여 사건 시각·속도·높이 등이 수렴하는지 검사합니다. 충돌에 필요한 힘과 충격량을 설명하지 않는 순간 위치 이동은 물리 성능으로 간주하지 않습니다.
- **에너지:** 탱크 내부에너지, 차량 기계에너지, 배터리와 손실은 서로 다릅니다. 차량의 운동에너지만 보존되어야 한다고 가정하지 않습니다. 배출 기체가 운반하는 에너지도 고려해야 합니다.

완벽하게 동일한 디지털 실차를 만들려면 질량분포, 관성행렬, 타이어·서스펜션, 방향별 추진기 성능, 팬·공력 지도와 실측 궤적이 필요합니다. 이 프로젝트의 목표는 가정과 오차를 확인할 수 있는 교육용 모델입니다.

## 세부 차량 기하와 질량 배치

`cgX/cgY/cgZ`는 차체의 기하 기준점에서 무게중심까지의 고정 오프셋(m)입니다. `inertiaRoll/inertiaYaw/inertiaPitch`는 그 무게중심을 지나는 X/Y/Z축의 주관성모멘트(kg·m²)입니다. 질량과 관성은 독립 입력이며, 모두 공개되지 않은 실차 값의 대용 가정입니다. 기체 소모로 총질량은 줄지만, 이 버전에서는 무게중심과 관성의 시간 변화·배출 기체의 회전 운동량은 여전히 생략합니다. 외형 파일로 질량 배치가 자동 추정되는 것은 아닙니다.

계산 위치 `state.pos`는 세계 좌표의 무게중심입니다. 차체 기하 기준점은 `bodyPosition = state.pos − R(q)cg`이며, 타이어·공력·팬·차체 충돌과 추진기 레버암에 같은 오프셋을 적용합니다. 따라서 무게중심을 앞쪽으로 옮기면 앞바퀴 정적 하중이 늘고, 높이면 가속·제동 시 앞뒤 하중 이동이 커집니다. 관성을 키우면 같은 토크의 각가속도가 작아집니다. 단순 수평 정적 조건에서는 `N_front/(mg) ≈ 1/2 + cgX/wheelbase`, 가속 중에는 `ΔN ≈ mah/wheelbase`로 이해할 수 있습니다. 실제 계산은 네 접점의 스프링·댐퍼 힘과 토크를 합하므로 자세와 과도응답도 포함됩니다.

`wheelbase`(휠베이스)와 `trackWidth`(윤거)는 바퀴 접점 기하를 바꿉니다. 앞바퀴는 Ackermann 기하에 따라 안쪽이 더 많이 꺾입니다. 휠베이스 L, 윤거 t, 회전 반경 R에서 `tan δ_inner = L/(R−t/2)`, `tan δ_outer = L/(R+t/2)`이며 실제 운동은 여전히 타이어 슬립과 마찰 한계로 결정됩니다. 서스펜션 링크 상세 기구학, 조향 탄성, 타이어 온도·마모, 실측 공력 지도까지 재현한 모델은 아닙니다.

## 이번 버전 검산

전기 주행 변경 후 자동 테스트 68개를 통과했습니다. 전기 구동·회생 에너지 상한·마찰 원·무마찰 조건·만충전·저속 정지·공중 접지 금지·방향 전환 입력을 검증합니다. 로컬 브라우저에서 가속 후 회생 전력과 마찰력 표시, 후진, 주행 중 D/R 전환 차단, 브레이크 정지와 비행 모드 전환·도약을 확인했습니다. 실측 자료와 맞춘 실차 검증이 아닙니다.

기존 57개 회귀 검사도 통과했으며, 기본 물리, 공유 도약 궤적, CG·하중 이동·관성·조향 기하와 스테이지 회귀 검사를 포함합니다. 3 m 시연의 최고 고도는 물리 시간 간격 2 / 1 / 0.5 ms에서 3.14757 / 3.14883 / 3.14946 m로 수렴합니다. 이 수치는 엔진의 수치 검산이며 실차 시험 결과가 아닙니다.

v1.3 공개 배포 당시 버전이 표시된 HTML·JS·CSS와 모델 데이터 등 35개 파일의 HTTP 200 응답과 로컬 SHA-256 일치를 확인했습니다. 실제 공개 브라우저에서 105개 원본 메시 목록, 브레이크 검색·선택·단독 확대, 분해 80%, 주행 모드 복귀 후 도약 상승을 확인했습니다. 모바일 390×844 화면의 목록·선택·설명도 로컬 브라우저에서 확인했습니다. 마지막 공개 화면의 콘솔 오류는 없었습니다. 사람의 WASD 전체 코스 완주와 트랙패드 핀치는 이번 브라우저 확인 범위에 포함하지 않았습니다.

## 스테이지와 공중 조종 (v1.2)

왼쪽의 **스테이지 시작** 버튼으로 7개 구조물과 3단계 코스를 시작합니다. 왼쪽 주행 게이트 → 공중 링 → 착지 패드에서 정지 순서입니다. 다음 목표는 노란색, 완료 목표는 녹색으로 표시합니다. 제한 시간은 시뮬레이션 시간 120초이며 일시정지·구조 탐색 중에는 진행하지 않습니다. R로 재시작하고, 자유 주행 버튼으로 구조물을 제거합니다. 시작·재시작 시 차량과 탱크를 초기화하며 진행 중에는 기체를 보충하지 않습니다.

지상 WASD는 모터·조향을 조작합니다. 공중 WASD는 **차량 기준** 전후·좌우 방향으로 약 17도 이내의 목표 기울기를 요청하고, 실제 추진기 토크와 추력으로 움직입니다. 키보드가 순간적인 수평 속도를 부여하지 않습니다. Space는 분사이며 고도 유지보다 우선합니다. 키를 놓으면 활성화된 자세 안정화가 수평을 회복합니다. Q/E는 요, 화살표는 수동 피치·롤입니다. 공중에서 접지력을 주지 않습니다.

처음에는 약 20–25 km/h로 접근해 링 약 8 m 앞에서 Space를 짧게 눌러 이륙하고, 하강 중 다시 분사해 감속하는 방식으로 연습할 수 있습니다. B는 지상 브레이크입니다. 착지 목표는 패드 반경 5 m 안에서 3개 이상 바퀴가 접촉하고, 수평 속력 1.5 m/s 미만·수직 속력 0.5 m/s 미만을 0.5초 유지하는 것입니다. 기체 부족이나 과도한 속도에서는 성공하지 못할 수 있습니다.

스테이지의 블록·아치와 충돌하며 박스 상면에는 개별 바퀴 접촉이 적용됩니다. 차체는 회전하는 상자(OBB), 장애물은 고정 축정렬 상자(AABB)로 근사합니다. 교차 검사와 충격량·마찰, 잔여 관통 보정을 사용하며 정밀 외형 메시 충돌·변형·파손 또는 일반적인 연속 충돌 검출은 아닙니다. 목표 링은 통과 판정용이며 먼 건물·콘·산은 배경입니다.

스테이지 완주 회귀 검사는 일반 모터·조향·자세·Space형 분사 입력으로 약 7.27초, 최고 약 2.73 m, 기체 약154.5 kg 잔량에서 완료했습니다. 조향·자세는 연속 피드백 입력을 사용했으므로 사람이 키보드로 쉽게 완주한다는 검증은 아닙니다. 자동 테스트 57개를 통과했으며 입력 전환, 벽·천장·플랫폼 충돌, 단계별 분해, 카메라 시점 유지, 코스 판정·완주를 포함합니다. 공개 사이트의 브라우저 확인 범위는 위 검산 항목에 기재했으며, 마우스 드래그·트랙패드 핀치와 WASD 전체 코스 완주는 이번 확인 범위에 포함하지 않았습니다.

## GitHub Pages 업데이트

`main`에서 `dist/`를 수정하고 다음 검사를 실행한 뒤 변경 사항을 커밋하고 `main`에 push합니다.

```sh
npm ci --ignore-scripts
npm run check
npm test
git push origin main
```

`.github/workflows/pages.yml`은 `main`의 `dist/**`, `tests/**`, `package*.json` 또는 workflow 파일이 변경되면 실행됩니다. 의존성 설치, JavaScript 문법 검사와 자동 테스트, 정적 진입점·모델 파일 검사를 통과한 뒤 `dist/`를 아티팩트로 업로드하여 배포합니다. README 등 문서만 변경한 push는 배포를 실행하지 않습니다. 필요하면 GitHub Actions의 **Deploy Roadster to GitHub Pages**에서 **Run workflow**로 수동 실행할 수 있습니다.

저장소 Settings → Pages의 Source는 **GitHub Actions**(`build_type: workflow`)를 유지합니다. `github-pages` 환경은 `main` 배포를 허용하도록 설정되어 있습니다. Actions에서 build와 deploy가 모두 성공한 다음 공개 URL을 확인합니다. 배포 주소는 https://leejuhan-1214.github.io/roadster/ 입니다.

2026-11-07 [배포 실행 42323860851](https://github.com/leejuhan-1214/roadster/actions/runs/42323860851)에서 build와 deploy 성공 및 공개 사이트 응답을 확인했습니다.

기존 `gh-pages` 브랜치는 보존된 스냅샷이며 현재 배포 소스가 아닙니다. `scripts/publish_pages.py`와 `scripts/deploy_github.py`는 이전 브랜치 배포 방식을 위한 도구이므로 현재 workflow 운영에서는 실행하지 마세요. 특히 `deploy_github.py`는 Pages 소스를 `gh-pages`로 다시 설정하므로 현재 자동 배포 설정을 되돌릴 수 있습니다.
