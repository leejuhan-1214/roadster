Roadster PC 작업 인계 — GitHub Pages 배포 완료

저장소: https://github.com/leejuhan-1214/roadster
공개 URL: https://leejuhan-1214.github.io/roadster/
배포 확인일: 2026-11-07 (한국 시간)

현재 상태:
- main 브랜치의 .github/workflows/pages.yml이 dist/를 GitHub Pages로 배포한다.
- Pages 설정은 build_type: workflow이며 Source는 GitHub Actions이다.
- github-pages 환경에서 main 브랜치의 배포가 허용되어 있다.
- workflow 도입 커밋: 63df26b.
- 성공한 실행: https://github.com/leejuhan-1214/roadster/actions/runs/42319605851
- 해당 실행에서 npm ci --ignore-scripts, JavaScript 문법 검사, 자동 테스트 47개와 정적 파일 검사를 통과했고 build/deploy가 모두 성공했다.
- dist/가 배포할 정적 파일 전체이며 Three.js, Tesla Roadster 모델과 라이선스가 포함되어 있다.
- 기존 gh-pages 브랜치는 이전 정적 배포 파일의 스냅샷으로 보존하며 현재 배포 소스로 사용하지 않는다.

확인한 배포 범위:
- 공개 HTML, JS와 Tesla scene.gltf/scene.bin 등을 포함한 34개 파일에서 HTTP 200 응답과 로컬 파일 대비 SHA-256 일치를 확인했다.
- 실제 공개 사이트의 브라우저에서 Tesla 모델 표시, 스테이지 시작, 자동 도약 시 고도 2.60 m 상승 표시, 구조 탐색 스크롤 분해 24%를 확인했다. 콘솔 오류는 없었다.
- 브라우저에서 WASD로 코스 전체를 완주하거나 마우스 드래그·트랙패드 핀치와 모든 입력 조합을 검증한 것은 아니다.
- 과거 브랜치 배포의 404와 배포 실패는 현재 배포 상태를 나타내지 않는다. 새 작업에서는 최신 Actions 상태와 공개 URL을 다시 확인한다.

이후 업데이트:
1. 현재 main과 원격 변경 사항을 확인하고 기존 커밋을 보존하며 통합한다. 강제 push하지 않는다.
2. main의 dist/와 필요한 소스·테스트를 수정한다.
3. npm ci --ignore-scripts, npm run check, npm test를 실행한다.
4. 변경 사항을 커밋하고 main에 push한다.
5. main의 dist/**, tests/**, package*.json 또는 .github/workflows/pages.yml 변경 시 workflow가 자동 실행된다. 문서만 바꾼 push는 배포하지 않는다.
6. 필요하면 Actions의 Deploy Roadster to GitHub Pages에서 Run workflow로 수동 실행한다.
7. build/deploy 성공과 기존 공개 URL의 응답을 확인한다.

이전 배포 도구 주의:
- scripts/publish_pages.py와 scripts/deploy_github.py는 gh-pages 기반의 이전 방식용이다. 현재 workflow 운영에서는 실행하지 않는다.
- 특히 deploy_github.py는 Pages 소스를 gh-pages로 다시 설정하여 현재 GitHub Actions 배포 설정을 되돌릴 수 있다.
- Pages Source는 GitHub Actions로 유지하고 공개 URL은 변경하지 않는다.
- Git 인증은 PC의 정상 인증 수단을 사용한다. 인증값을 출력하거나 파일·대화·저장소에 넣지 않는다.

조작: 마우스 회전, WASD 이동/공중 제어, Space 분사, R 리셋.
스테이지 시작 버튼과 구조 탐색 모드의 스크롤 분해 기능이 구현돼 있다.
실제 차량의 비공개 사양은 가정값이며 정밀 실차 재현을 주장하지 않는다.
